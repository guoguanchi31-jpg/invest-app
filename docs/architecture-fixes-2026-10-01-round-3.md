# 日期与目标状态边界修复验收

日期：2026-10-01。对应
[业务日期与实体状态 ADR](adr/2026-10-01-business-date-and-entity-state.md)。

## 修复结果

| 问题 | 最终行为 |
| --- | --- |
| P1 日期输入、比较、备份契约不一致 | 新 API 仅接受规范 ISO 日期；日期按语义比较；schema 10 和旧备份仅兼容无歧义 `YYYYMMDD` |
| P2 刷新失败后直接切月被旧目标状态拦截 | 月份读取确认与目标实体 `stateKey` 分离；后续真实状态提交可取代旧终态意图 |

schema 10 覆盖账户建账日、流水/交易发生日、行情日、目标日期、目标记录日和快照日。
迁移无法确认的格式会停止部署，不静默改变资金语义；日期归一后的重复快照保留最新
派生事实。备份格式版本保持 v8，因为字段集合未变化。

## 验证

- HTTP 创建账户和流水传入 `20260901`/`20260928` 均返回 422，且不产生财务事实。
- 历史账户及期初流水由紧凑日期迁移为 ISO；随后正常支出 10 元，余额 100 → 90。
- 同一账本导出后可预览恢复；紧凑日期旧备份可规范化并恢复，斜杠日期返回 422。
- 歧义存量使 schema 10 失败且版本停留在 9；迁移可重复执行。
- 快照日期归一发生唯一键碰撞时只保留最新一条。
- 目标真实浏览器路径为：完成成功 → GET 503 → 直接切到下一月 → 恢复 → 再次完成；
  三次 PATCH 使用三个不同操作键，最终状态为 completed。
