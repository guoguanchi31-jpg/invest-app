# 业务日期与实体状态意图契约

日期：2026-10-01。状态：已实现。补充
[互斥命令 ADR](2026-10-01-command-conflicts-transfer-audit.md)。

## 问题

Python `date.fromisoformat()` 接受 `YYYYMMDD`，旧校验却把原字符串直接存入 TEXT。
账户生效逻辑再用字符串比较，导致紧凑建账日后的正常支出不影响余额；同一账本导出
后也无法通过恢复校验。另一方面，目标状态意图按“目标 + 状态”保存，却只能由带
月份的资源读取释放；写入成功但刷新失败后直接切月，旧 completed 意图会拦截后续
再次完成。

## 决策

1. `domain/dates.py` 是业务日期唯一解析入口。新 API 只接受真实存在的
   `YYYY-MM-DD`，首尾空白可去除；存储值始终为十位 ISO。
2. `affects_balance`、投资建账日和历史基线按日期对象比较，不使用 TEXT 排序。
3. schema 10 迁移 accounts、transactions、investment_trades、prices、goals、
   goal_records、snapshots 的日期列。仅历史 `YYYYMMDD` 自动转换；可空字段空值转
   NULL；其他格式中止迁移并报告定位。数据库随后增加格式和真实日历日期保护。
4. 旧 JSON 备份使用相同兼容规则。预览可规范化 `YYYYMMDD`，歧义格式返回 422；
   当前格式的直接校验仍要求规范 ISO。
5. 月份资源键继续控制读取确认。目标状态另外声明实体 `stateKey`；新的状态写入
   真正提交后，淘汰同一目标更早的非未知状态意图。重复点击不触发淘汰，
   `unknown/processing` 也不允许被覆盖。

## 存量规则

- 规范 ISO 日期保持不变。
- `YYYYMMDD` 无损转换为 `YYYY-MM-DD`。
- nullable 日期的 NULL/空白保持无日期语义。
- 无效日、斜杠日期、缺位日期和时间戳不自动猜测，必须人工更正后重试迁移。
- 快照日期转换后发生唯一键碰撞时，保留 `created_at` 较新者，时间相同则保留
  ID 较大者；快照是派生估值，不合并金额。

## 验证

回归覆盖 API 对紧凑建账日/流水日返回 422、schema 10 双次执行、历史账户和期初
流水转换、100 元账户支出 10 元后余额为 90、备份预览及恢复、歧义存量阻断、
快照碰撞收敛，以及桌面/平板/手机的“刷新失败后直接切月”目标状态循环。
