# 互斥命令、转账量化与审计展示契约

日期：2026-10-01。状态：已实现。补充
[资源确认与审计载荷 ADR](2026-10-01-resource-history-audit-contracts.md)。

## 问题

资源确认可能在切月前已成功却未被行级意图消费；响应丢失后，目标恢复等反向操作
可能复用旧键或覆盖迟到写入。备份允许省略 SQL 默认字段，但领域校验直接读取字段。
目标、预算等嵌套审计无法由平面字段比较展示。十位汇率对高计价单位不能表达任意
两位本位币金额，转账写入和恢复的舍入顺序因而冲突。

## 决策

1. 资源确认一旦满足身份、资源键和序号条件就锁存在意图上；只在提交不再 pending
   后释放。月份切换不撤销已获得的确认。
2. 同一实体的互斥状态命令声明 `conflictKey`。旧结果未知时，通过只读命令状态接口
   按家庭和操作用户确认。只有 committed、expired、invalidated 允许新命令；
   processing、unknown、缺失及网络错误均保留旧键并阻止新写入。
3. 备份规范化和领域校验共享账户状态默认值，只补 SQL 允许省略的字段。
4. 审计展示按 `entity_type + payload_version` 使用白名单结构。目标分配按 member_id，
   分类预算按 category_id，分类承担按 category_id + member_id 配对；数据库行 ID
   变化不制造删除/新增假象。未知版本明确显示为历史载荷，不猜测其中 ID。
5. 转账使用转出腿未舍入的高精度本位币值推导收款汇率，同币种直接沿用转出汇率。
   保存的本位币金额仍为两位。恢复只对完整、守恒的转账收款腿接受由十位汇率量化
   决定的半单位残差；转出腿和其他流水继续严格校验。

## 安全边界

- 命令状态接口不返回请求指纹、正文、响应或其他用户的存在性。
- 缺失命令不是“可重试新意图”的证据，避免旧事务提交后覆盖新状态。
- 转账残差上限由到账金额和数据库精度计算，不是固定宽容值；篡改任一双腿本位币
  金额、引用、账户、日期或撤销状态都会失去例外资格。
- 审计只展示业务字段白名单，不递归输出未知对象或敏感字段。

## 兼容性

不增加 schema 或备份版本。既有 v1-v8 备份继续读取；旧转账收款汇率可能由已舍入
本位币反推，仍落在同一量化边界内。旧前端持久化操作没有 conflictKey 时，
目标状态按同路径、账户归档/恢复按声明的兼容路径发现，升级后可安全完成确认。
