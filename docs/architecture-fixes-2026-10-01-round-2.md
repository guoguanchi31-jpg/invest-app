## 修复结果

复审发现的 4 个 P2 问题均已修复，并补上复核时识别的“未知结果后执行反向状态”
共享缺陷。改动沿用现有模块化单体边界，未修改 schema、备份版本或真实账本。

| 问题 | 最终行为 |
| --- | --- |
| 成功确认后切月仍复用旧行级意图 | 成功读取立即锁存确认，提交结束后消费；9 月确认后切 10 月仍可完成恢复和再次完成 |
| 投资账户备份缺默认字段返回 500 | 规范化与领域校验共享 SQL 默认值，缺失 `is_liability` 的投资账户可预览和恢复 |
| 嵌套目标、预算审计显示无变化 | 按版本化实体结构展开；目标状态/进度、预算总额、成员和分类承担均按稳定业务键比较 |
| 转账汇率量化导致失败或无法恢复 | 同币种保留源汇率；跨币种从未舍入源值推导；仅完整转账收款腿使用有界量化残差 |
| 响应丢失后反向状态可能重放旧响应 | 目标状态和账户归档/恢复声明互斥组；新写入前按家庭和用户确认旧命令服务端终态 |

## 关键验证

- 目标行级动作覆盖同月循环、确认后切月、GET 失败后手动重载、pending 防重。
- 命令冲突覆盖旧命令 committed 后放行、服务端缺失时阻止、原意图继续复用原键，
  并验证其他家庭不能读取命令状态。
- 转账覆盖 1 KRW / 0.0048 同币种、10,000 USD → 250,000,000 VND、
  导出校验与恢复往返、篡改拒绝及资金事务回滚。
- 审计覆盖目标状态、目标存取、预算总额/分类/成员、投资账户与持仓前后状态、
  转账账户/流水 ID 碰撞、未知版本和敏感未知字段。
- 真实浏览器展开嵌套审计，桌面、平板、手机均验证表格位于弹窗内且无横向溢出。
